================================================================================
SECURITY AND COMPLIANCE NOTES: LOCAL LINUX FLEET LAB
================================================================================

1. NETWORK EXPOSURE
-------------------
- Target VMs use private host-only network addresses:
    app01: 192.168.56.11
    app02: 192.168.56.12
    app03: 192.168.56.13
- No public bridged interfaces or WAN port forwards are configured.
- By default ("nginx_bind_private_ip_only: true"), nginx binds explicitly to
  each VM's private lab IP address on port 80 rather than all interfaces.

2. SSH AND PRIVILEGE HARDENING
------------------------------
- Ansible connects over SSH using per-VM private keys generated by Vagrant (or
  explicitly configured keys for external VMs).
- Baseline compliance ("roles/common") configures
  "/etc/ssh/sshd_config.d/99-fleet-compliance.conf" to enforce:
    PermitRootLogin no
    PasswordAuthentication no
- Kernel hardening parameters are applied in
  "/etc/sysctl.d/99-fleet-compliance.conf":
    net.ipv4.ip_forward = 0
    kernel.kptr_restrict = 1

3. REPORT DATA HYGIENE
----------------------
- Runtime JSON and Markdown reports written to "reports/" record only operational
  metadata (hostnames, private IPs, OS versions, pending update counts, package
  names, service states, HTTP status codes, and error messages).
- SSH keys, passwords, and environment secrets are never collected or rendered
  into report templates.
- Generated reports are ignored by git via ".gitignore" so runtime host data is
  not committed to version control.
